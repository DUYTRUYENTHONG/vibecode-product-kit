# Product planning

Find the existing PRD, related implementation and tracker story before adding scope. Separate observed behavior, public research and assumptions. Keep one existing accountable owner.

For each slice, specify user outcome, entry/success/error/recovery journey, exclusions, dependencies and test scenarios. State metric definitions, observation window and target; unknown measurements stay not_measured. Confirm capacity before dates or sprint commitments.

Map frontend/backend interfaces explicitly where the journey crosses them. Keep permission, migration and independent QA prerequisites visible. Do not silently turn blocked core acceptance into future work to claim completion.

Deliver the edited requirement/story and a short decision/change log. Tracker writes need an authorized connector and readback; a local PRD update is not a Jira update.

# Product requirements

Status: DRAFT. This scaffold is not approved scope.

## User and problem
Name the primary user, current friction and observable outcome. Separate observed research from assumptions.

## Scope
List included journeys and explicit exclusions. Use stable feature IDs from project.json.

## Journeys
For each goal, describe entry, happy path, empty/loading/error states, cancellation and recovery. Include anonymous and authenticated actors where relevant.

## Acceptance and measures
Each feature needs observable criteria, named test scenarios, a metric definition and a target. Unknown measurements stay not_measured, not zero.

## Constraints and dependencies
Record data ownership, authorization, accessibility, performance, privacy, external providers and compatibility requirements. Keep implementation contracts in architecture notes or the story, not hidden in copy.

## Decisions and amendments
Record date, decision owner, changed requirement IDs and downstream test/sprint impact. Preserve prior evidence. Open questions have an owner and next action.
